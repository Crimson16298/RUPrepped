# Presage SmartSpectra camera POC

This is an isolated command-line verification harness, not a production frontend. It uses the official Node SDK's native camera path, so Electron is not required for the first real-camera check.

## Prerequisites

- Windows x64, macOS Apple Silicon, Linux x64, or Linux ARM64. Linux requires glibc 2.35+.
- Node.js 20+ (the verified host uses Node 24.19.0).
- A connected, OS-permitted camera and a SmartSpectra API key from `physiology.presagetech.com`.

## Run

```powershell
npm install
$env:SMARTSPECTRA_API_KEY = '...'
$env:SMARTSPECTRA_MEASUREMENT_CONSENT = 'yes'
$env:SMARTSPECTRA_SESSION_TIMEOUT_MS = '90000' # optional; 90 seconds by default
npm run measure
```

Alternatively, create an untracked `experiments/presage-poc/.env` containing `SMARTSPECTRA_API_KEY=...`. The measurement script loads that exact file relative to its own POC directory, so it does not depend on the shell's working directory. Do not commit the file.

The process emits JSON Lines. `validationStatus` gives the SDK's readiness code and human hint; `metric` is output only when the SDK has emitted decoded readings. No values are generated by this harness. Stop with Ctrl+C to release the camera and dispose the SDK. This POC explicitly disables the SDK's otherwise-default aggregate telemetry; decide on production telemetry and user disclosure with the team.

## Bounded live diagnostic

Run this only from ordinary Windows PowerShell, not a restricted sandbox. It requires an explicit local consent flag before it opens the camera, makes one bounded SDK session, and never retries a non-retryable authentication error. It does not call a guessed HTTP endpoint: SmartSpectra's documented SDK lifecycle is the only authentication path it uses.

```powershell
cd C:\Users\zach0\RUPrepped\experiments\presage-poc
$env:SMARTSPECTRA_DIAGNOSTIC_CONSENT = 'yes'
$env:SMARTSPECTRA_SESSION_TIMEOUT_MS = '30000'
npm.cmd run diagnose
```

The JSON result uses `PASS` only for camera discovery or actual decoded metric samples. `FAIL: authenticationFailure` means the SDK reported installed error code 2; it cannot distinguish an invalid/revoked key from an account entitlement problem when the service returns the same HTTP 401. `BLOCKED: noValidMeasurements` means no valid sample arrived before the session ended; it is not a physiological conclusion. `network` is intentionally `UNKNOWN` because Presage does not document a public SDK-authentication hostname for safe direct probing.

The POC passes the SDK's documented `kError` log level, while retaining its public error events. MediaPipe may still emit one-time initialization warnings directly to stderr before its logger is configured; those warnings are external model-runtime diagnostics, not an API-key or measurement failure, and this POC does not hide them.

### Validation feedback

The live diagnostic coalesces repeated `validationStatus` events into `session.validationSummary`, with a documented code, count, explanation, and camera-adjustment action. It deliberately does not retain raw SDK hint text. In particular, code `7` means the chest is not visible or is too far away for chest/breathing metrics; code `16` means the face is too low in the frame. For the next test, place the camera so one face and the unobstructed upper chest are visible, move the face upward in frame (or tilt the camera down), use even lighting, keep still, and run a 90-second session. This is a framing/readiness correction, not evidence that authentication succeeded.

The harness requests Presage's documented breathing and cardio bundles. It records only the documented `breathing.rate`, `cardio.pulseRate`, and `cardio.hrv.rmssd` samples (when present), alongside the SDK event timestamp and the source sample timestamp. Breathing rate is reported in breaths/minute and pulse rate in bpm; this harness deliberately omits an RMSSD unit because the installed SDK declaration does not define one. Presage documents confidence as 0–100 and says breathing, pulse, and HRV need warm-up windows (30, 12, and 60 seconds respectively) before acting on values.

## Electron follow-up

For the eventual desktop integration, use the SDK's documented Electron entry points rather than this CLI: `@smartspectra/node-sdk/main`, `/preload`, and `/renderer`; call `bindSmartSpectraIpc(window)` in main and use the renderer SDK with its browser-owned media stream. Do not use this POC's camera logic as a production renderer implementation.
