# Presage SmartSpectra camera POC

This is an isolated command-line verification harness, not a production frontend. It uses the official Node SDK's native camera path, so Electron is not required for the first real-camera check.

## Prerequisites

- Windows x64, macOS Apple Silicon, Linux x64, or Linux ARM64. Linux requires glibc 2.35+.
- Node.js 20+ (the verified host uses Node 24.19.0).
- A connected, OS-permitted camera and a SmartSpectra API key from `physiology.presagetech.com`.

## Run

```powershell
npm install
SMARTSPECTRA_API_KEY=replace_with_your_presage_physiology_api_key
$env:SMARTSPECTRA_MEASUREMENT_CONSENT = 'yes'
$env:SMARTSPECTRA_SESSION_TIMEOUT_MS = '90000' # optional; 90 seconds by default
npm run measure
```

SMARTSPECTRA_API_KEY=replace_with_your_presage_physiology_api_key

The process emits JSON Lines. `validationStatus` gives the SDK's readiness code and human hint; `metric` is output only when the SDK has emitted decoded readings. No values are generated by this harness. Stop with Ctrl+C to release the camera and dispose the SDK. This POC explicitly disables the SDK's otherwise-default aggregate telemetry; decide on production telemetry and user disclosure with the team.

## Bounded live diagnostic

Run this only from ordinary Windows PowerShell, not a restricted sandbox. It requires an explicit local consent flag before it opens the camera, makes one bounded SDK session, and never retries a non-retryable authentication error. It does not call a guessed HTTP endpoint: SmartSpectra's documented SDK lifecycle is the only authentication path it uses.

```powershell
cd C:\Users\zach0\RUPrepped\experiments\presage-poc
$env:SMARTSPECTRA_DIAGNOSTIC_CONSENT = 'yes'
$env:SMARTSPECTRA_SESSION_TIMEOUT_MS = '30000'
npm.cmd run diagnose
```

The JSON result uses `PASS` only for camera discovery or actual decoded metric samples. `FAIL: authenticationFailure` means the SDK reported installed error code 2; it cannot distinguish an invalid/revoked key from an account entitlement problem when the service returns the same HTTP 401. `BLOCKED: noValidMeasurements` means no valid sample arrived before the session ended; it is not a physiological conclusion. `network` is intentionally `UNKNOWN` because Presage does not document a public SDK-authentication hostname for safe direct probing.

The POC passes the SDK's documented `kError` log level, while retaining its public error events. MediaPipe may still emit one-time initialization warnings directly to stderr before its logger is configured; those warnings are external model-runtime diagnostics, not an API-key or measurement failure, and this POC does not hide them.

### Validation feedback

The live diagnostic coalesces repeated `validationStatus` events into `session.validationSummary`, with a documented code, count, explanation, and camera-adjustment action. It deliberately does not retain raw SDK hint text. In particular, code `7` means the chest is not visible or is too far away for chest/breathing metrics; code `16` means the face is too low in the frame. For the next test, place the camera so one face and the unobstructed upper chest are visible, move the face upward in frame (or tilt the camera down), use even lighting, keep still, and run a 90-second session. This is a framing/readiness correction, not evidence that authentication succeeded.

The harness requests Presage's documented breathing and cardio bundles. It records only the documented `breathing.rate`, `cardio.pulseRate`, and `cardio.hrv.rmssd` samples (when present), alongside the SDK event timestamp and the source sample timestamp. Breathing rate is reported in breaths/minute and pulse rate in bpm; this harness deliberately omits an RMSSD unit because the installed SDK declaration does not define one. Presage documents confidence as 0–100 and says breathing, pulse, and HRV need warm-up windows (30, 12, and 60 seconds respectively) before acting on values.

## Proposed active-session bridge

`src/session-measurement-adapter.mjs` is a reusable local-only bridge for a
future interview host. It associates a real, normalized SDK event with the
active interview's actual `sessionId`, but only after explicit consent. It
emits a minimal summary only when `validationCode === 0` and at least one
sample has confidence at least 70 and `stable: true`. It never emits raw
frames, video, SDK hints, or a fabricated reading.

The host calls `grantConsent()` only after a user opt-in, and calls
`revokeConsent()` to immediately stop summaries. Missing camera input, denied
consent, invalid SDK readiness, low quality, or SDK failure yield a status and
must not interrupt the interview. The adapter does not persist data and must
not be wired to telemetry until the team approves consent wording and
retention.

The current FastAPI process must not access the user's webcam. For the first
integration demo, run the existing SmartSpectra POC or a local Node companion
alongside the interview host, then send only consented summaries across a
reviewed boundary. The repository's Electron files are placeholders; an
Electron owner must implement the documented SmartSpectra main/preload/
renderer integration before Electron can host capture.

## Loopback companion transport

For a Chrome demo, `npm.cmd run companion` starts a local-only service on
`127.0.0.1:8765`. The SDK captures in the Node process (the installed SDK
documents that `useCamera()` captures in that process); Chrome never receives
frames. This is the recommended demo runtime. Electron is the fallback once
its owner implements the documented main/preload/renderer bridge.

Before starting the companion, set a non-committed local capability token in
the same PowerShell process. It must be at least 32 characters and must also
be supplied by the local React development configuration; never put it in a
repository file.

```powershell
$env:PRESAGE_COMPANION_TOKEN = '<local-random-token-at-least-32-characters>'
$env:PRESAGE_COMPANION_ORIGINS = 'http://localhost:5173,http://127.0.0.1:5173'
npm.cmd run companion
```

The service accepts only the listed browser origins and an
`X-Presage-Capability` request header. Use `fetch`, not native `EventSource`,
for the SSE stream because `EventSource` cannot attach that header.
`@ruprepped/presage-companion-client` is the reusable browser-safe client for
this exact contract. It refuses non-loopback URLs, so the capability cannot
accidentally be sent to a remote service. Its source is owned by Person 3 at
`packages/presage-companion-client/`; it is not copied into frontend code.
Person 4 should add it as a local package dependency, then import it by its
package name:

```powershell
cd C:\Users\zach0\RUPrepped\frontend
npm.cmd install --save file:../packages/presage-companion-client
```

```ts
import { createPresageCompanionClient } from "@ruprepped/presage-companion-client";
```

The package includes TypeScript declarations and imports no Node-only module,
so it can be bundled by Vite without expanding Vite's filesystem allowlist.

### Local-development capability handoff

The Presage API key stays only in the Node companion. React needs a separate
32+ character local capability value solely to send the required HTTP header.
For a hackathon development demo, use an ignored `frontend/.env.local` with a
fresh token generated for that local run. A `VITE_*` value is visible to
browser JavaScript and must be treated as a limited local development
credential, **not** a production secret. It must never contain the Presage API
key, be committed, appear in a URL, or be logged.

From the repository root, generate and write the same short-lived token to the
current PowerShell process and the ignored frontend configuration without
printing it:

```powershell
$bytes = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
$token = [Convert]::ToBase64String($bytes)
$env:PRESAGE_COMPANION_TOKEN = $token
Set-Content -Path .\frontend\.env.local -NoNewline -Value "VITE_PRESAGE_COMPANION_URL=http://127.0.0.1:8765`nVITE_PRESAGE_COMPANION_TOKEN=$token`n"
$env:PRESAGE_COMPANION_ORIGINS = 'http://localhost:5173,http://127.0.0.1:5173'
```

Start the companion from that same PowerShell process so it inherits the
token, then start Vite in a second terminal. Delete `frontend/.env.local` or
generate a new token after the demo.

| Route | Request | Result |
| --- | --- | --- |
| `POST /v1/presage/start` | `{ "sessionId": "ses_...", "consent": true }` | Starts one active session after consent. Duplicate same-session starts are safe; another session is rejected. |
| `GET /v1/presage/status` | Header only | Current session and status. |
| `GET /v1/presage/events?sessionId=ses_...` | Header only, fetch-SSE | Status and validated measurement events for the active session only. |
| `POST /v1/presage/stop` | `{ "sessionId": "ses_..." }` | Revokes consent, stops/destroys the SDK, and clears association. |

Every event has `schemaVersion: "1.0.0"` and `emittedAt`. A real measurement
event has this exact shape (optional metrics are absent when the SDK did not
emit them):

```json
{
  "schemaVersion": "1.0.0",
  "type": "measurement",
  "sessionId": "ses_example",
  "observedAt": "2026-10-11T03:00:00.000Z",
  "emittedAt": "2026-10-11T03:00:00.000Z",
  "metrics": [
    { "metric": "pulseRate", "value": 72, "unit": "bpm", "confidence": 90, "stable": true, "measuredAt": "2026-10-11T03:00:00.000Z" },
    { "metric": "breathingRate", "value": 14.2, "unit": "breaths/min", "confidence": 90, "stable": true, "measuredAt": "2026-10-11T03:00:00.000Z" }
  ],
  "quality": { "validationCode": 0, "confidence": 90, "stable": true }
}
```

`hrvRmssd` is emitted only when the SDK supplies it; its unit remains omitted
because SDK v3.4.0 does not define one. `observedAt` is the POC's SDK callback
receipt time; `emittedAt` is the companion transport time. Status values are
`awaiting_consent`, `starting`, `warming_up`, `measuring`,
`quality_insufficient`, `unavailable`, `stopped`, and `error`.
`permission_denied` is not separately detectable from the installed Node SDK:
its input-unavailable condition maps conservatively to `unavailable`.

## Electron follow-up

For the eventual desktop integration, use the SDK's documented Electron entry points rather than this CLI: `@smartspectra/node-sdk/main`, `/preload`, and `/renderer`; call `bindSmartSpectraIpc(window)` in main and use the renderer SDK with its browser-owned media stream. Do not use this POC's camera logic as a production renderer implementation.
